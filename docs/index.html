01 / Text replacement

Not hidden. Just softened*

Your own rules, not a hidden policy. This demo processes only the text below. Input is not saved or sent to a server.

Filtered output

Whole words, case-insensitive. Inflections need their own rules. This is not contextual moderation and cannot guarantee that unwanted content is removed.

02 / Explicit permission

One source. Chosen by you.

Request another tab or window through your browser’s picker. This is an unfiltered visual preview—it does not read page text, censor pixels or modify the shared tab. Do not share sensitive content.

Nothing is shared. No audio, recording or uploads.

The picker may offer screens as well as tabs; choose carefully. You cannot access another person’s browser without their separate sharing action and permission. Switching sources requires stopping and choosing again.

03 / Actual tab text

Change text where you read it.

The companion Chromium extension applies the same rules to ordinary page text after you explicitly enable it on the current tab. It includes a stop-and-restore control and a small asterisk next to replacements.

Prototype boundaries

No blanket all-site permission, background tab surveillance or content uploads. Password fields, forms, editable regions, scripts and embedded frames are excluded. Canvas, images, video, audio and shadow DOM are not filtered. Some dynamic sites may be incompatible; this is not a security boundary.

04 / Measure before shipping

A small English model.
Only if it beats the baseline.

Stage 1

Define & label

Opt-in, licensed English examples. Annotate spans, context and safe alternatives. Include quotations, benign lookalikes and dialect variation. No training on shared tabs by default.

Stage 2

Train & compare

Benchmark rules against a compact span classifier. Use source-separated evaluation, abstention and an explicit user lexicon for replacements—not unconstrained generated rewrites.

Stage 3

Optimize & validate

Export a quantized browser candidate. Measure accuracy, download size, memory and p95 latency on CPU and optional GPU. Keep rules available if the model is unavailable.

No dataset, trained weights or benchmark results are included yet. OCR for video text and speech recognition for audio are separate future workstreams; a text classifier alone cannot censor a stream.
